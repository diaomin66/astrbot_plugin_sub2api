## 当前可用边界

| 项目 | 交接报告及插件处理 |
| --- | --- |
| 绑定申请、账号查询 | 后端报告已部署；插件保持 v1 路径、身份字段、Bearer 认证及幂等算法 |
| 站内确认 | 登录后进入 `/profile`，点击「管理 QQ 绑定」，手动输入机器人回复的确认码 |
| 旧确认链接 | `/user/qq-bindings` 兼容跳转到 `/profile#qq-bindings`，普通管理按钮不跳转 |
| 用户认证 | 沿用 Sub2API 用户登录；插件不读取用户 token，不确认、拒绝或解绑用户申请 |
| 签到、打劫 | 生产返回 `FEATURE_DISABLED`；插件新安装默认关闭，明确提示后端未开放 |
| 财务验收 | 在途请求预留和异步余额缓存边界未完成；不能靠数据库标志或插件开关强行启用 |
| 公网域名 | 交接报告指定 IP 实例 UI 通过，而公网域名返回不同页面/错误 MIME，尚未验收 |
| HTTPS | 交接 IP 浏览器探测允许自签名证书；插件保持严格验证，不能把浏览器通过当作 TLS 通过 |
| 真实用户/QQ 联调 | 未完成；浏览器合成账号/拦截 API 测试不等于真实用户绑定成功 |

以上生产状态来自交接报告，不是本次重新探测公网、登录用户、执行 SQL 或修改服务器的结果。

## 本地插件适配

1. 默认关闭签到和打劫，保留显式启用配置用于未来已验收后端，不擅自改写现有配置文件。
   旧版本若保存过 `enabled=true`，升级后不会自动清零；运维应主动确认关闭。
2. 将申请和待确认提示对齐个人设置弹窗，不拼接未经验证的域名/IP，
   不把邮箱、身份或确认码放进 URL，也不自动打开或替用户确认。
3. 帮助文字区分「插件规则」与「后端开放状态」；后端拒绝时不能显示奖励/转账成功。
4. TLS 证书或握手失败只给安全提示，不降低验证要求，不自动重试此类错误。
5. 增补后端请求/版本/幂等校验错误提示；未知错误继续脱敏，令牌和原始响应不落日志。
6. 账号、消息字段拒绝 DEL 控制字符，以匹配实际后端校验器。

## 联调顺序

1. **先由有权限的运维修复/确认域名链路**：核对 DNS、CDN/Worker、源站、Host/SNI
   和路径转发。不要仅凭 SPA HTML 响应或 HTTP 200 判断接口和静态资源正确。
2. 证书需由客户端信任，且匹配所填写域名/IP；不得使用 `ssl=False`、`verify=False`
   或 `curl -k` 的结果作为生产接入通过证据。自有 CA 须经过运维批准并部署正确的信任链。
3. 确认 bridge JSON 与主站 JSON envelope 不混用：bridge 为 `{ok:true,data:...}`。
   静态 JS/CSS 应返回正确 MIME 和 `Cache-Control: no-store`，且不要添加 `?v=...`；
   当前后端中间件拒绝 query string。
4. 使用令牌授权的 QQ AppID 和实际 AstrBot 平台实例 ID 配置插件。令牌只在受保护的
   运行时配置/环境变量中提供，不粘贴到聊天、工单、文档或 Git。
5. 保持两个资金开关关闭，先验证 `/额度帮助`、未绑定 `/我的账号`。
6. 用户本人在 QQ 发起 `/绑定 邮箱`，登录自己的站点账号，在弹窗手动确认。
   随后 `/绑定状态` 应显示已绑定。测试取消/拒绝/过期时，不得出现已绑定或余额权限。
7. 真实 QQ 群与私聊身份分别验收；第三方 @ 数据需要真实群消息验证，
   不能用纯文本昵称/QQ 号代替平台 OpenID。
8. 在主网关预留/缓存集成、真实消费和充值并发测试、预算及运维无中断发布方案通过前，
   不开放签到/打劫。本插件本地测试不能替代这些验收。
