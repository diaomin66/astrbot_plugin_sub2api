# Sub2API 账号与互动插件

面向 AstrBot 的 QQ 官方机器人插件。保留仓库原有部署配置，不修改运行中的服务。

独立仓库：`https://github.com/diaomin66/astrbot_plugin_sub2api`。
该仓库根目录就是插件根目录，不包含 AstrBot 宿主机部署配置。

## 开发边界

插件通过专用 bridge API 对接你二开的 Sub2API，**不是仅填原版 Sub2API 地址就能使用**。
账号归属、绑定确认、随机结果、额度账本、签到去重、护盾和打劫冷却必须由 Sub2API
服务端在数据库事务内处理。插件不保存用户余额，不持有全权管理员 API Key，
不使用两个独立的加减余额请求模拟转账。

本仓库没有 Sub2API 源码，因此交付的是**插件实现 + 后端接口契约 + 自动化测试**；
没有修改或部署你的 Sub2API，也没有伪造已到账的余额。二开时按 `docs/SUB2API_BRIDGE.md`
实现接口、站内确认页面与事务逻辑后才能连接真实账号。

## 功能

| 命令 | 行为 |
| --- | --- |
| `/绑定 user@example.com` | 申请绑定邮箱；在站内输入本次确认码并确认后生效 |
| `/绑定状态`、`/我的账号` | 查询当前身份绑定、余额、今日签到、护盾和打劫冷却 |
| `/签到` | 每个 Sub2API 账号每自然日一次，后端随机发放额度 |
| `/打劫 @群友` | 双方均绑定才可参与；成功转入额度，失败赔偿对方 |
| `/余额`、`/额度` | 当前账号状态和额度 |
| `/护盾`、`/冷却` | 查看剩余护盾与打劫冷却 |
| `/额度帮助` | 查看命令及当前玩法规则 |

所有额度均为 Sub2API 可用余额的同一单位，**不是 API Key token 数或订阅重置额度**。
默认值只是可修改的玩法初始配置，不代表任何真实账号余额。

### 初始玩法

- 签到：`0.10～0.50`；以 `Asia/Shanghai` 自然日计。
- 打劫：`40%` 成功；成功从目标转入 `0.05～0.20`，失败赔偿目标 `0.01～0.05`。
- 成功和失败均触发发起者 `3600` 秒冷却，并给目标 `7200` 秒护盾。
- 主动发起有效打劫会解除自己的护盾。余额不够时最多转走付款方的可用余额，不得为负。
- 发起者至少需要拥有失败赔偿下限；目标余额必须大于零；同账号小号不能互抢。
- 将失败赔偿上下限均设为 `0` 可关闭失败赔偿；冷却/护盾设为 `0` 可关闭对应机制。
- 绑定、签到、余额和冷却以**后端账号**为准，不能通过跨群、切换私聊、重启插件或换绑绕过。
- 这些经济约束由后端事务执行，插件只提交配置并展示经过格式校验的结果。

## 安装

1. 使用 AstrBot `>=4.29.1`，配置 QQ 官方机器人 WebSocket 或 Webhook 平台。
   本实现对照本仓库部署版本 `v4.29.1` 的接口编写，未声称已完成真机兼容验证。
2. 将**本目录**放入 AstrBot 的 `data/plugins/astrbot_plugin_sub2api/`。
   从独立仓库克隆时，仓库根目录即为插件根目录；私有仓库需使用有权限的 GitHub
   账号克隆后手动安装，不要把访问令牌写进仓库 URL、插件配置或日志。
   如果使用包含宿主机 `compose.yml` 的外层工作区，只复制其中的插件目录。
   在当前部署布局下，宿主机路径应为 `/opt/astrbot/data/plugins/astrbot_plugin_sub2api/`。
3. 按 AstrBot 插件管理流程安装 `requirements.txt` 并加载/重载插件。
4. 打开插件配置，填写：
   - `connection.base_url`：Sub2API 站点地址，不含 `/api/v1`。
   - `connection.bridge_token`：二开后端发放的专用随机服务令牌，至少 32 字符。
   - `connection.qq_app_id`：QQ 开放平台 AppID。
   - `connection.platform_id`：AstrBot 里该 QQ 机器人实例的 `id`，不是 QQ 号或群号。
5. 确保 AstrBot 命令唤醒前缀中包含 `/`；群内按你的 QQ 平台配置先 @机器人再发命令。
6. 保存配置后重载插件，使连接及玩法配置生效。测试 `/额度帮助` 和 `/我的账号`。

也可以设置 `SUB2API_QQ_BRIDGE_TOKEN` 环境变量，优先于配置文件中的令牌。
若使用现有 Docker 部署，需自行将该变量显式传入 AstrBot 容器；单独写入宿主机 `.env`
不等于容器已获得变量。插件没有改动现有 compose 或 Nginx 文件。

### 配置面板

`_conf_schema.json` 定义四组后台配置：

| 分组 | 可调整内容 |
| --- | --- |
| 连接 | URL、令牌/环境变量、QQ AppID、平台实例 ID、超时、可信内网 HTTP 开关 |
| 绑定 | 申请有效期、允许群内绑定开关 |
| 签到 | 功能开关、时区、奖励上下限 |
| 打劫 | 功能开关、成功概率、成功额度/失败赔偿上下限、打劫冷却、护盾时长 |

额度和概率以字符串配置，保留十进制精度；最多 6 位小数。概率为 `0～1`，
例如 `0.4` 表示 40%。配置不合法时拒绝启用额度操作，并在日志说明字段错误。
服务端必须再次校验并设定单笔上限、每日发放预算和业务开关，不能仅信任插件配置。

## QQ 身份与隐私边界

- 使用 QQ 官方消息中的 OpenID，不把昵称、QQ 号码或用户输入的标识当作身份证明。
- WebSocket 与 Webhook 使用同一 `provider=qq_official` 命名空间。
- 身份键为 `(app_id, scope, openid)`；群聊 `qq_group` 与 C2C 私聊 `qq_c2c`
  不自动合并。需要分别确认到同一 Sub2API 账号，才能共用账号额度及冷却。
- `/打劫` 仅使用结构化 `At` 或平台原始 `mentions`；不会从正文中的 `@昵称`、
  `<@...>`、CQ 字符串、引用消息或任意数字猜测目标。
- 若 QQ 权限或事件未下发目标 OpenID，明确回复无法识别，不降级到不安全的文本匹配。
  须在实际机器人权限和群聊中验证能否收到第三方 @ 信息。
- 默认允许群内绑定以满足群身份验证。**群内邮箱、确认码、余额回复对群成员可见。**
  插件不回显邮箱；但它无法撤销用户原始消息。关闭群内绑定后，需自行提供站内群身份验证。
- 当前不支持 QQ 频道、OneBot 或其他平台；不做自动跨平台账号匹配。
- 插件命令停止后续事件传播，避免正常命令继续交给 LLM；无法保证抢先执行的其他插件
  或 AstrBot 本身的消息日志从未接触邮箱，请一并检查宿主日志与插件执行顺序。

## 后端二开

完整请求/响应、确认页面、幂等、事务和数据库约束见 `docs/SUB2API_BRIDGE.md`。
需要实现四个服务接口：

```text
POST /api/v1/qq-bot/bindings/request
POST /api/v1/qq-bot/account
POST /api/v1/qq-bot/checkin
POST /api/v1/qq-bot/robbery
```

不要把这些约定误认为原版 Sub2API 既有接口。站内确认和解绑使用登录用户认证，
不能使用机器人服务令牌代替用户确认。

## 安全与重试

- 默认要求 HTTPS，校验证书，拒绝重定向，不继承环境代理。HTTP 只可显式用于隔离可信内网。
- Bearer 令牌仅具 bridge 权限并绑定 AppID，不应授予通用管理员或任意用户余额修改权限。
- QQ 消息 ID 生成稳定幂等键；网络错误/502/503/504 最多以相同请求重试一次。
  后端必须同时落账和保存幂等结果，否则自动重试不安全。
- 响应丢失时提示“可能已执行”，不是误报操作失败。新的 `/打劫` 消息是新的业务请求。
- 后端业务错误不自动重试；禁止两个独立 HTTP 请求模拟一笔转账。
- 不记录请求正文、邮箱、令牌或原始错误响应；不回显服务端任意文本。

## 本地测试

在独立插件仓库根目录执行：

```powershell
python -m pip install -r requirements.txt pytest ruff
python -m pytest tests -q
python -m ruff check .
python -m ruff format --check .
```

测试包括配置边界、QQ 两种传输身份、真实 @、邮箱格式、命令路由、错误脱敏、
HTTP 认证、响应大小限制、重定向阻断、重复请求键及“已提交但响应丢失”的重试。
HTTP 测试使用本地测试服务器，命令测试使用 AstrBot API stub，不需要连接真实账号。
这些测试**不能替代** Sub2API 真正数据库事务、站内确认授权和 QQ 真机联调。
